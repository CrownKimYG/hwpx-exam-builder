# 단계별 출제 QA — 2026-09-25

## 구현 범위

- 문제은행 / 출제 / 시험지 화면 분리.
- 시험지 → 과목 비율 → 단원 묶음 → 확인 → 결과 5단계.
- 과목별 비율, 선택적인 교재 비율, 단원 묶음 수량·난이도, 묶음 해제.
- 과목/교재의 정수 배분 나머지 분산, 동일 시험지의 단원 중복 방지, 전체 생성 묶음의 문항 중복 방지.
- 기존 교재 수량·조건표·혼합 배치, 템플릿, 원본 미리보기, HWPX 출력 연결 유지.

## 자동 검사

- JavaScript 테스트 151개 통과 (새 추첨·단계 탐색·템플릿 회귀 포함).
- Python 테스트 4개 통과.
- 프로덕션 빌드 및 diff 공백 검사 통과.
- 3:2 과목 배정, 1:1 나머지 분산, 묶음당 1문항, 교재 2:1 배정, 난이도, 같은 시드 재현, 과거 문항 제외 확인.
- NaN 비율, 중복 묶음, 단원 부족, 미사용 문항 부족, 1,000문항 초과를 거부하는 경로 확인.

## 실제 브라우저

로컬 개발 주소의 기존 저장 은행 2개(총 937문항)를 사용했다. 실서비스의 브라우저 저장소는 수정하지 않았다.

- 저장된 기존 출제 방식과 시험지 복원.
- 5문항 × 7부, 수학Ⅰ:수학Ⅱ 3:2 입력 및 단원 묶기.
- 생성 성공 후 결과 단계 자동 이동.
- 결과를 문항 코드가 아닌 과목·단원·교재로 확인, 편집 화면 이동.
- 묶음·비율·문항 수·생성 시험지가 새로고침 후 복원되는지 확인.
- 실제 11부 HWPX 생성: 앱의 구조/페이지 검증 후 결과 파일 11개 다운로드 완료.
- 실행 중 브라우저 콘솔 오류 없음.

## 비기능 검증

- 데스크톱 및 390px 화면의 실제 배치 확인.
- 320px / 390px 단원 묶음 화면과 320px 시험지 편집 화면에서 문서 가로 폭 초과 없음.
- 기본 입력·선택·버튼은 네이티브 요소이며, 현재 단계와 선택 상태를 접근성 속성으로 제공.
- 단계 이동 시 현재 단계로 초점 이동, 단원 선택 후 초점 복원.
- 오류는 alert로 표시하고 조건을 완화해 생성하지 않음.
- 로컬 합성 데이터(2,000문항, 20단원): 100문항 약 15ms, 500문항 약 196ms, 1,000문항 약 694ms. 장치·조건에 따라 달라질 수 있음.
- 탐색 150,000회 / 2.5초 상한 및 추첨 전 단원·문항 부족 검사 적용.

## 범위 제한

- 모든 브라우저/운영체제의 호환성이나 별도 스크린리더 전수 검사는 수행하지 않았다.
- 균등 배분은 주어진 수동 조건 내에서의 선택 우선순위이며, 복잡한 조건의 전역 최적화를 보장하지 않는다.
- 과목 표기는 정규화하지만 이름이나 단원 번호가 다른 단원을 추정해 합치지는 않는다. 사용자가 묶음으로 지정한다.
