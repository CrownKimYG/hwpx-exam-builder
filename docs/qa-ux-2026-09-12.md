[핵심 기능 QA](qa-core-2026-09-12.md)에 추가한 사용자 경험 점검이다. 제품 코드 수정 없이 실제 브라우저 조작·스크린샷·DOM 상태·관련 소스를 교차 확인했다.

범위: 첫 방문, 저장된 작업 재입장, 은행별 문항 수, 조건표 탭, 직접 입력 오류, 출력 설정, 키보드 조작, 1280×720 데스크톱과 390×844 모바일 폭. 기존 사용자 데이터 대신 5174 주소의 QA 자료를 사용했다. 첫 방문은 저장 데이터가 없는 `localhost:5174`에서 확인했다.

판정: **개선 필요 — UX 결함 6건, 사용성 개선 제안 2건**. 실사용자 참여 평가나 정식 접근성 인증 결과는 아니다.

## 재현한 UX 결함

### UX-01 · P2 — 모바일 출력 설정이 화면 오른쪽으로 잘림

- 재현: 390×844 화면 → 출제 작업 열기 → 하단 `출력 설정` 열기.
- 관찰: 팝업 왼쪽 x=232, 너비 340, 오른쪽 x=572. 화면 너비 390을 넘어 **182px가 밖으로 나감**. 스크린샷에서 템플릿 파일명과 인계 저장 버튼의 오른쪽이 잘린다.
- 영향: 설정 내용을 충분히 읽거나 버튼 전체를 확인하기 어려움.
- 원인: `web/src/styles.css:364`, `:384`, `:393`. 작은 화면에서 팝업을 트리거의 왼쪽에 맞추지만, 트리거 자체가 하단 바의 오른쪽 열에 있음.
- 권장: 모바일에서는 화면 좌우 여백에 맞춘 고정 패널이나 하단 시트로 표시. 닫기 버튼을 제공.
- 완료 기준: 320·390·768px 폭에서 패널 전체와 모든 조작 요소가 화면 안에 들어오고, 확대해도 내용을 읽을 수 있음.

### UX-02 · P2 — 데스크톱에서 핵심 문항 수 설정이 출제 버튼 뒤에 가려짐

- 재현: 1280×720, 은행 2개·시험지 4개가 있는 작업 복원. 출제 구성 스크롤을 맨 위에 둠.
- 관찰: `#quick-body`의 실제 높이는 210px, 내부 내용 높이는 420px. 은행별 문항 수 영역은 y=377부터 시작하는데 고정된 출제 동작 영역이 y≈346부터 위를 덮는다. 최초 화면에는 은행 이름·수량 입력 대신 출제 방식과 출제 버튼만 보임.
- 영향: `문제은행별 문항 수`를 선택하고도 정작 수량을 어디서 바꾸는지 알기 어려움. 내부에서 스크롤하면 접근 가능하므로 기능 자체가 불가능한 것은 아님.
- 원인: `web/src/styles.css:346`, `:370–373`의 좁은 내부 스크롤 영역과 sticky 동작 영역 조합.
- 권장: 은행별 수량을 첫 화면의 우선 정보로 배치하고, 출제 버튼은 스크롤 내용과 분리해 가리지 않도록 구성. 상세 조건만 접거나 스크롤하도록 조정.
- 완료 기준: 은행 1~2개 기준으로 이름·수량·출제 버튼이 동시에 읽히고 조작 가능.

### UX-03 · P2 — 새 문제은행 추가에 키보드로 접근할 수 없음

- 재현: 첫 방문 → 키보드로 `파일 추가 · 가져오기` 열기 → Tab 반복.
- 관찰: 포커스가 `folder-input → files-input → handoff-input` 순서로 이동하고 `new-bank-input`은 건너뜀. `new-bank-input`은 `display:none`, 연결된 `label`은 `tabIndex:-1`.
- 추가 관찰: 다른 파일 입력은 너비·높이 1px, opacity 0인 요소로 포커스가 이동해 화면에 현재 위치 표시가 보이지 않음.
- 영향: 마우스를 사용하지 않는 사용자는 새 은행 추가 버튼에 도달할 수 없고, 다른 파일 등록 동작도 현재 포커스를 식별하기 어려움.
- 위치: `web/index.html:29–37`, `web/src/styles.css:277` 및 숨김 파일 입력 스타일.
- 권장: 실제 버튼으로 파일 선택기를 열거나, 숨긴 입력의 포커스가 연결된 화면 버튼에 표시되도록 구성.
- 완료 기준: Tab으로 각 등록 동작에 도달하고 포커스가 보이며 Enter/Space로 선택기를 열 수 있음.

### UX-04 · P2 — 문항 코드 오류가 입력 필드의 접근성 정보에 연결되지 않음

- 재현: 시험지 문항 코드에 `1-3` 입력.
- 관찰: 화면에는 `문항 코드는 01-003 형식으로 입력해야 합니다: 1-3`이 표시되고 다운로드도 차단됨. 그러나 해당 textarea의 `aria-invalid`와 `aria-describedby`는 모두 없음. 개별 오류 문구는 일반 p 요소로 생성됨.
- 영향: 보조기기를 사용하는 사용자가 해당 입력의 오류 상태와 수정 방법을 연결해서 파악하기 어려움. 실제 스크린리더 낭독까지는 검증하지 않음.
- 위치: `web/src/main.js:1742`, `:1796`.
- 권장: 오류 상태와 설명을 입력 필드에 연결하고, 오류 변경을 적절히 알리며 정상 입력 시 오류 상태를 해제.
- 완료 기준: 필드에서 오류 여부·구체적 수정 방법을 읽을 수 있고 정상 코드로 고치면 오류가 제거됨.

### UX-05 · P3 — 은행 조건 탭에서 방향키 이동이 동작하지 않음

- 재현: 조건표 모드 → QA 수학 A 탭에 포커스 → 오른쪽 방향키.
- 관찰: 포커스·선택이 A에 그대로 남음. 두 탭 모두 tabIndex 0. Tab으로 B에 이동한 뒤 활성화하는 우회는 가능.
- 영향: 탭으로 표현된 UI의 키보드 사용 방식이 일관되지 않음.
- 위치: `web/src/main.js:1518–1519`.
- 권장: 좌우 방향키·Home/End 이동과 선택 탭의 포커스 관리를 구현하거나, 일반 선택 버튼 UI로 의미를 정리.
- 완료 기준: 마우스 없이 은행 탭 이동·선택·해당 조건 입력이 가능하고 포커스와 선택 상태가 명확함.

### UX-06 · P3 — 떠 있는 출력 설정에 빠른 닫기 동작이 없음

- 재현: 출력 설정 팝업 열기 → Escape → 팝업 밖의 출제 구성 제목 클릭.
- 관찰: 두 경우 모두 details의 open 속성이 유지됨. 원래 `출력 설정`을 다시 눌러야 닫힘.
- 영향: 다른 내용을 가리는 팝업을 닫는 방식이 쉽게 드러나지 않음. 기능 차단은 아니지만 작은 화면에서 UX-01과 겹쳐 불편이 커짐.
- 권장: 명시적인 닫기 버튼 및 Escape 지원. 바깥 클릭 닫기는 입력값을 보존하는 방식으로 적용.
- 완료 기준: 키보드·터치로 쉽게 닫히며 포커스가 트리거로 복귀하고 설정은 보존됨.

## 사용성 개선 제안 — 기능 결함과 별도

1. **첫 방문의 시작 동작을 직접 노출.** 빈 목록 위에는 비활성 `선택한 은행으로 출제`가 보이고, 실제 시작 동작은 접힌 `파일 추가 · 가져오기` 안에 있다. 파일 드래그를 사용하지 않는 초보자를 위해 빈 상태에서 `문제은행 파일 선택`을 주요 버튼으로 보여주고, 현재 은행이 없는 상태의 `현재 은행에 파일 추가`는 숨기거나 설명을 바꾸는 편이 좋다.
2. **작은 화면의 고정 바를 축소.** 390×844에서 고정 하단 바 높이는 214.5px로 화면의 약 25%를 차지한다. 다운로드 버튼과 요약을 우선 보여주고 세부 출력 옵션은 펼치도록 하면 문제 목록을 확인할 공간이 늘어난다. 팝업을 닫은 일반 화면에서는 가로 넘침이 없었다.

## 정상 확인한 항목

- 빈 목록은 원본 등록 후 재사용 가능하다는 설명을 제공한다.
- 작업 복원 진입에는 은행 수·시험지 수가 표시된다.
- 잘못된 문항 코드는 기대 형식과 오류 값을 함께 안내하고 다운로드를 차단한다.
- 조건표의 누락 오류에는 해당 은행명과 누락 문항 위치가 표시된다.
- 시험지별 총 문항 수와 은행별 구성 요약을 제공한다.
- 일반 버튼·은행 탭에서는 키보드 포커스 테두리가 보인다.
- 모바일에서는 출제 구성·목록·원본 미리보기가 한 열로 배치되고, 일반 화면의 문서 너비는 화면 너비 390px와 일치한다.
- 앞선 기능 QA에서 비우기 되돌리기, 자동 저장, 재입장 복원을 확인했다.

## 권장 수정 순서와 한계

먼저 모바일 팝업 위치, 파일 등록의 키보드 접근, 데스크톱 핵심 수량 입력 노출을 수정한다. 다음으로 입력 오류 연결과 탭·팝업 키보드 동작을 정리한다. 기능 QA에서 발견한 문항 누락·순서 오류는 이 UX 목록과 별도로 우선 처리해야 한다.

실제 휴대폰 터치·가상 키보드, 브라우저별 차이, 스크린리더 낭독, 색 대비 수치 전체, 사용자 과업 수행 시간은 검증하지 않았다. 태블릿 검증 완료로 간주하지 않는다. 화면 크기 임시 설정은 원래대로 복원했다. 제품 코드는 변경하지 않았다.
