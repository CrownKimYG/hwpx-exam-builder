## 발견 사항

### P1 — 마지막 문항의 다음 페이지 내용 누락

- 위치: `web/src/parser.js:285–291`
- 조건: 한 구역의 마지막 미주 문항이 명시적인 페이지 나눔을 넘어 이어짐.
- 재현: 문항 시작 + `pageBreak="1"`인 필수 조건 문단 + 마지막 선택지 문단을 입력.
- 기대: 세 문단 모두 같은 문항에 포함.
- 실제: `copyStart: 0, copyEnd: 1`, 본문은 `마지막 문항 시작`만 남음.
- 영향: 문제의 조건·선택지가 빠진 시험지가 생성될 수 있음. 현재 코드는 페이지 나눔만으로 문항 종료를 결정한다. 실제 종료 표식을 구분하고 다음 페이지의 본문은 보존해야 한다.

### P2 — 11개 이상 구역에서 원문 문항 순서 변경

- 위치: `web/src/parser.js:224–226`
- 재현: 각 구역에 한 문항씩 있는 `section0.xml`부터 `section11.xml`까지 분석.
- 기대: `0, 1, 2, …, 11`.
- 실제: `0, 1, 10, 11, 2, 3, …, 9`.
- 영향: 문항 코드가 원문 순서와 달라져 잘못된 문항을 선택할 수 있음. 구역 개수 기준이며 페이지 수 기준은 아니다.
- 원인: 파일명을 문자열 기본 정렬. 문서의 구역 순서를 따라야 하며, 같은 정렬을 사용하는 템플릿·인계 코드도 함께 점검해야 한다.

### P3 — 한국 시간 오전의 ZIP 파일명 날짜가 전날로 표시

- 위치: `web/src/main.js:2227`
- 실제: 2026-09-12 05:50 KST 생성 파일이 `시험지_3개_2026-09-11.zip`으로 저장됨.
- 원인: UTC 기준 `toISOString()`으로 날짜 생성.
- 기대: 사용자 현지 날짜를 파일명에 사용.

앞의 두 문제는 다음 명령으로 재현할 수 있다. 이 스크립트는 관찰 결과를 출력하는 진단 도구이며 통과/실패 자동 테스트가 아니다.

```sh
pnpm exec node scripts/qa-core-edge-cases.mjs
```

## 검증 한계

- HWP 바이너리 원본 변환은 기존 변환 모듈 테스트 범위까지만 확인했다. 실제 HWP 원본을 한컴과 비교하지 않았다.
- 수능특강 약술형·서술형 채점표의 특수 파서는 기존 자동 테스트를 실행했다. 해당 유형의 실제 원본 전체를 새로 가져와 확인하지 않았다.
- 사용자 출력 템플릿 누름틀·스타일, 주관식·서술형 변환, 이미지 워터마크, 채점표 너비는 기존 자동 검사 범위이며 모든 조합의 UI 왕복 검사는 아니다.
- 한컴오피스 실제 열기·인쇄, 페이지 넘침·양면 빈 쪽의 시각 검증, 모바일·여러 브라우저, 대용량 스트레스·생성 취소는 이번에 검증하지 않았다.
- Python Streamlit 화면은 실행하지 않았으며 웹 앱 중심 QA이다.
- 따라서 기존 자동 검사 통과를 모든 원본·모든 출력 옵션의 품질 보장으로 해석하면 안 된다.

## 산출물과 환경

- 진단 스크립트: `scripts/qa-core-edge-cases.mjs` (합성 입력만 사용).
- QA 자료는 공개 배포물에 추가하지 않았다. 다운로드 결과는 사용자 Downloads 폴더에 있으며, 원문 내용은 이 보고서에 포함하지 않았다.
- 5174 주소에 QA용 은행·설정이 저장되어 있다. 기존 5173 주소의 사용자 은행과 출제 이력은 변경하지 않았다.
- 브라우저 다운로드 이벤트 대기는 한 차례 시간 초과했으나, 실제 파일 저장과 앱 완료 상태를 확인해 앱 생성 실패와 구분했다.
